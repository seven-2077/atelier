## 2. 场景要点

- **建筑**：奶油白三层，连续圆弧转角；一层圆弧双开门（上下两块玻璃、奶油门梃、黄铜把手、上亮子、台阶与自拟门牌 18）；二层连续白铁艺阳台（包住圆弧转角），铁艺花纹用 Canvas 生成后 alpha 裁切，能读出卷草/圆环；三层安静窗列，压顶线脚收边。窗户有窗套、窗台、窗楣；暖窗按窗位分成亮、中、暗几档，不是整排一样亮。
- **蓝花楹**：两棵程序化树，使用不同 seed / 主干长度 / 分叉数 / 冠幅 / 倾斜。左树更低更横、靠镜头，右树更高、从楼右侧升起并越过屋顶。树干、枝条、末端细枝为合并几何，花簇为 InstancedMesh 的透明花卡，沿枝端分布；没有用圆球做树冠。左树右下做了裁切，保证圆弧门口在默认机位可读；两棵树的轮廓、分叉和花簇密度不同。
- **街角**：深色微缩底座，近侧马路有虚线与斑马线，前缘底座侧面可见；人行道铺地、路缘、树池、路灯、紫色长椅、门口杂志架、稀疏落瓣都在。
- **光**：After Dark 使用深蓝紫渐变夜空与很淡的圆形天光；暖窗、门廊、阳台底灯和路灯是暖源；路灯只照亮附近树干、花瓣和铺地，没有全屏霓虹或假神光片。没有加 Bloom，柔感来自色调映射、发光材质和局部灯。
- **文字**：左侧 HTML/CSS 英文生活方式杂志排版；衬线刊名、手写标题、小 caps 栏目，右下和画面右缘没有社交组件、点赞数字或品牌字样。

## 3. 可读性自检

- **圆弧门口**：默认机位及左右各 13.5° 轨道端点上均可见；双开门、玻璃、门框、台阶可辨。左树右下的花卡裁切了，未把门吞掉。
- **二层铁艺阳台**：默认机位可见整段栏杆和卷草细节；轨道两端仍可读。
- **紫色长椅**：位于左树外侧、朝向街角，默认机位和轨道两端都完整可见；点亮后紫色板条和靠背可辨。
- **左侧刊名/标题**：树冠在文字后面，`Jacaranda Days` 与 `SYDNEY` 未被吞。白天模式下正文叠在花冠上时对比度偏弱，已用浅色 scrim 和文字光晕缓解，但仍不是最理想的状态。
- **树形**：两棵均为弯曲分叉主干 + 末端细枝 + 花卡，不是球体；左树冠仍偏密，虽然能看到空隙和枝干，但还不算完全通透，下一轮可以再减一层花卡。

## 4. 三段光与交互

- Daylight：薄蓝天空、柔和日光、冷色窗玻璃、浅紫花冠，树影偏长。
- Golden Hour：低空暖杏 + 上部蓝色，奶油建筑吃侧暖光，花冠偏粉紫。
- After Dark：主样张，深蓝紫夜空，窗与门廊成为主光源，暗部沉下去。
- 三段通过左下 `Daylight / Golden hour / After dark` 文字按钮平滑过渡（约 2.4 s），没有游戏 HUD。
- 少量飘落花瓣（110 片）与地面落瓣，不是铺满路面的花毯。
- 轨道/缩放已在 Chrome + SwiftShader 下实测：方位 -0.79 ~ -0.29 rad，距离 31.8 ~ 40，无控制台报错；门口/阳台/长椅在端点仍可读。

## 6. 诚实的已知问题

1. 右侧马路在默认机位里被透视压得很薄且多处于树影中；近侧马路、虚线和斑马线读得最清楚，右侧更像路边暗带。下轮可把右侧路缘再拉开一点。
2. 22.5° 俯角下能看到一块平屋顶；已用女儿墙和较浅屋面收住，但没有做坡屋顶。
3. 白天模式下正文叠在花冠上时对比度仍偏弱；夜间和黄昏没有这个问题。
4. 左树冠的密度仍高于理想状态；它已经不是圆球、也有明显空隙，但还可以更透。
5. 没有使用 Bloom / 后期景深；如果你要更接近参照图那种柔光，需要加很轻的 bloom 或柔光叠加。
6. 截帧日志里的 404 是 favicon；已在页面里补 `data:` favicon，不影响成图。
